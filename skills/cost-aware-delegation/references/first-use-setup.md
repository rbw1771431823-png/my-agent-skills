# 安装与首次使用设置

供安装Agent或首次实际使用的Agent执行；不依赖特定平台、模型或Agent身份。已有配置直接复用，只补本次需要的缺项。

## 何时执行

- 安装Agent实际读取本Skill时，可在安装中完成设置。只复制文件的安装器不会执行这里的询问；未完成时由第一次使用本Skill的Agent接续，不把复制成功说成已配置。
- 首次使用没有有效设置、换平台/机器，或已选模型/能力发生变化时，核对受影响项。普通续用不重复整套访谈。
- 只读查询、仅讨论或尚不需要委派/目录脚本时，只查当前任务需要的信息，不为设置改文件、创建分身或运行目录生成。

## 先查，再问

1. 读当前用户指令、当前项目的有效协作/权限映射及已有设置入口；用户最新决定优先。核对原任务/执行者/产物，不因初始化重新派出进行中或已完成任务。沿既有指针找到设置，不扫描其他项目或整台电脑。
2. 从实际工具清单、可读文档或最小只读检查，确认任务所需能力：文件读/写、命令运行、委派/续接/取回结果、模型及推理选项、上下文隔离；只有要用目录脚本才检查PowerShell。区别“可调用”“已请求”“实际已核实”和“未知”。不为探测启动收费任务、申请账户、安装软件或更改权限。
3. 只问会影响当前动作且无法查明的用户选择，合并为少量通俗问题，说明推荐项和影响。例如：
   - 首次实际需要委派且模型策略未定：“分工时沿用这个平台已有的默认模型，还是固定使用你指定的模型？”只列当前确认可用的选择；没有可核对清单时请用户提供已知选择，不编造型号/价格。平台不能选模型时说明限制，询问是否接受可用方式。
   - 有委派能力但允许方式不清：“这项任务允许按需要交给其他Agent，还是由当前Agent完成？”已有授权或禁令时直接遵守。
   - 首次获准维护项目但资料/写权不明：“哪个文件是最新进度，哪些文件允许更新？”能从项目说明确定的不再问。
   - 确需目录导航而范围不明：“为哪个项目文件夹维护目录？哪些资料、输出或缓存不列入？”只记录/查询不询问未用到的目录设置。
   - 本次需要保存且没有约定入口：“这些选择是仅本次使用，还是保存在本机的个人设置／当前项目的协作说明里，方便以后沿用？”Agent给出已核实的建议位置，不让用户猜系统目录。
4. 用户未回答时保持相关选择待定，不把等待当同意；继续有明确授权且无依赖的部分。没有委派能力时按运行配置允许的直接处理方式继续；不得把自查说成独立复核。缺运行环境只暂停依赖它的脚本，不影响一般记录/判断。

## 保存并能再次找到

个人模型偏好、平台能力与机器运行环境保存在使用方已有的个人设置位置；项目资料入口、写权和目录语义保存在该项目的既有协作/配置位置，不写回可分发的Skill或示例。两份Skill可共用同一设置记录，各自缺项各自补，不要求另一份Skill存在。

已有授权且保存位置明确时直接写入。没有约定时，建议采用目标平台实际支持的用户设置文件或项目协作文件，经用户选择后使用；遵守其写权，不强制某个文件名、隐藏目录、Git、TASK或平台配置格式。若另存设置文件，在平台会读取的既有用户/项目指令入口加入简短指针，并核对指针可读；写入口也须在授权内。若无可靠自动读取入口，可在下一次交包提供该位置，但必须说明跨会话不会自动加载，不声称永久生效。

只保存必要项目，不写密钥、Cookie、账号凭证、完整工具日志或原始私人资料。可用以下短格式记录，字段名可随平台调整：

- 范围与读取入口：个人／本机平台／当前项目，以及实际设置位置或指针。
- 已确认选择及依据：沿用哪条用户/项目决定；委派方式；实际可选模型/推理设置或采用平台默认；上下文与并发限制。
- 能力状态与核对时间：已确认、仅请求、未知、不可用；本次需要的命令/文件/目录运行能力。
- 项目映射：引用既有权威资料和写权，不另建平行进度库。
- 尚缺项及恢复条件：需要谁回答、何时才影响执行。

写后读回并核对入口。不能写入或用户只要本次使用时，保留当前会话中的选择，明确“本次已选、尚未持久保存”，后续不重复询问同一已回答项。跨会话无法读取旧选择时说明缺口，只询问确实缺失的相关项。

迁移或设置失效时，保留旧选择的适用范围/历史，只重核受影响能力。旧平台的模型、工具名、安装路径和AgentID不自动带入新平台；先提供当前真实支持的选择，不能静默换模型或扩大费用/权限。回报分别写清“已安装”“首次设置已完成或待答”“实际已验证的能力”，不把它们合并称为全部可用。
