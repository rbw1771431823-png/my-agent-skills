# 使用示例

以下为虚构项目，展示如何提出任务与判断结果。它们不是默认目录骨架，也不要求采用某种任务编号。

## 1. 查清哪个决定仍有效

项目有两份活动安排，一份写9点，另一份写10点；文件没有明确替代关系。

```text
请用项目记录员查清活动目前几点开始。
只读查询，列出原始依据和冲突，不按文件时间替我决定。
```

合理结果是查阅相关上下文，说明当前缺少什么依据，必要时请用户确认。没有证据时，不能自行宣布10点已生效，也不应为了查询生成目录或修改设置文件。

## 2. 只同步用户确认的局部变化

用户已确认新时间为10点，地点保持社区图书室。

```text
请按项目既有记录方式，把已授权的现行安排更新为10点。
地点及其他条件不变；保留早先9点的历史记录和这次替代关系。
只修改本次明确授权的位置，完成后给出变更和检查依据。
```

合理结果是实际更新允许写入的位置，核对旧口径与未完项；范围外关联文件列为待协调。收到消息、写入成功、复核通过应分别表达，不能只生成草稿就说全部同步完成。

## 3. 接手工作时避免重派

项目里已有执行者、部分产物和未完成的复核。

```text
请用按任务分工续接这项已授权任务。
先核实现有执行者、版本和产物，再决定直接处理还是委派。
交清资料、写权和验收，不重复安排已完成或进行中的实现。
```

合理结果是沿原进度继续，补真正缺失的工作。只有需要时才建立新角色；产品取舍与尚未查清的关键判断仍由协调责任人处理。

## 4. 平台只有当前 Agent

```text
这个平台不能创建其他Agent。请在已有授权内直接处理这次小改，
做必要自查；如果任务要求独立复核，把该环节单独留待安排。
```

合理结果是完成适合直接处理的部分，如实区分自查与独立复核。Skill 不会因为平台缺能力而虚构分身或更改验收名称。

## 5. 换电脑或平台

```text
请检查这里已有的Skill设置。能继续用的保留，
旧平台才有的模型、工具或路径不要照搬。
先查当前环境，只问会影响这次任务的缺项，并说明设置怎样保存和再次找到。
```

合理结果是核对相关能力，保留用户已确认且仍适用的选择，把平台设置放在使用方。不能将私人配置写回公共 Skill，或未经授权安装软件和启动业务。
