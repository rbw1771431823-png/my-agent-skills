# 兼容与验证范围

这里区分指令设计、实际验证与仍需使用方确认的条件。

## 平台与能力

通用核心没有固定模型品牌、推理档位、平台工具名或 Agent 身份。平台接法是按需附页；OpenAI 的界面元数据可忽略。这不表示每个平台都会自动发现 Skill，或拥有相同的文件、委派和隔离能力。

| 需要做的事 | 使用条件 | 能力缺失时 |
|---|---|---|
| 查历史、核对已确认决定 | 能读 Skill 和所需资料 | 说明不可访问范围，不把未查到说成不存在 |
| 更新文件 | 对应写入能力、明确写权和可核对来源 | 可提供待写内容，但不能称已保存 |
| 派给其他 Agent | 可用的委派/续接工具及任务授权 | 当前 Agent 可直接处理适合的部分，不冒称已派遣 |
| 独立复核 | 未参与实现的独立人员或角色 | 保留该环节待办，不用自查代替 |
| 保存首次设置 | 授权位置及后续可读入口 | 说明只在当前会话使用或需手动传入 |
| 自动生成/检查目录 | 命令能力、PowerShell、项目写权 | 一般记录可继续；目录脚本标为未运行 |

安装不会授予开发、收费、账户访问、删除或外部发布权限。

## 已实际验证

目前证据来自本机 Windows 的隔离文件样例及独立复核：

- 完整安装、读取安装后的 Skill，分别核对文件与交付包。
- 资料冲突时向模拟用户提问；收到答案后保存到使用方入口并读回。
- 续用现有设置，按当前来源回答，只读查询不改文件内容或修改时间。
- 从指定入口重新找到外部设置；旧平台配置失效时重新选择，不静默换型号或沿用旧工具/编号。
- 仅复制安装后的首次实际使用补接；两份 Skill 可分别使用。
- 单 Agent、禁止委派和缺少 PowerShell等能力条件下的相关处理。其中能力限制是条件模拟，没有卸载软件或更改系统权限。
- 原有资料、局部替代关系、历史保留、写权与目录检查边界按样例核验。

目录工具的普通路径已在 Windows PowerShell 5.1 和 PowerShell 7验证。PowerShell 7通过深层目录样例；Windows PowerShell 5.1的隔离长路径样例失败，这项限制仍保留。

## 尚未验证

- 其他 Agent 产品、其他操作系统及其安装器的实机兼容性。
- 全新会话是否会自动读取使用方选定的设置入口。
- 本次平台解耦版本在其他平台上的实际委派、模型路由或完全上下文隔离。
- 所有任务的长期一致性，以及 Token、费用或耗时的固定改善比例。

实际使用时按当前平台工具和可读文档确认；请求参数、实际回执与未知项分别记录。隔离样例通过不等于真实业务或所有平台通过。

## 各类“通过”的含义

- 文件和链接检查：证明交付结构完整。
- 设置保存与读回：证明指定位置确有内容；自动跨会话加载还取决于平台入口。
- 目录检查：证明导航与文件名、链接、配置一致。
- 项目功能/内容验收：由具体任务的要求、实际使用路径及证据判断。

这些结论不能互相代替。改了版本或环境后，只重核受到影响的部分。
